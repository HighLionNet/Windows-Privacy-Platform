# History — Version 1.0

**Milestone date:** 2026-07-24  
**Document role:** Historical record of the first public-quality desktop release, including final presentation polish.

---

## Context entering v1.0

Through v0.9.5 the platform delivered a stable read-only knowledge engine: collectors, binders, ValueSemantics, educational precedence, provenance, relationship graph, and catalog maturity. Presentation was CLI + TUI only.

Backend architecture was independently treated as frozen for GUI work.

---

## Goals of v1.0

1. Professional desktop application (WPF) that feels like modern Microsoft software  
2. Presentation layer only — consume existing Models / Scanner pipeline  
3. Machine Overview dashboard  
4. Domain pages + Setting Detail (full knowledge surface)  
5. Knowledge Explorer, Conflicts, Search  
6. Async scan with status  
7. Preserve CLI and TUI  
8. No architecture redesign  
9. Final polish: visual hierarchy, breadcrumbs, mode scaffold, expandable disclosure, remembered shell state  

---

## What shipped

### New project

- `WindowsPrivacyPlatform.App` — WPF `net8.0-windows`, presentation host only  
- References Models, Core, Logging, KnowledgeBase, Validator, Scanner  
- Does not reverse dependency direction  

### Application shell (final polish)

- Top bar: title, **Mode** control (Inspect active / Modify disabled scaffold), version, scan time, search, Scan button  
- Left navigation **grouped**: Machine · Privacy · Security · Windows · Applications · Knowledge · About  
- Collapsible sidebar (toggle + remembered state)  
- Breadcrumb bar for orientation  
- Content host with constrained reading width  
- Status bar: status text, catalog count, conflict count, validation, “Never modifies Windows”  
- Window size / position remembered under `%LocalAppData%\WindowsPrivacyPlatform`  

### Views

- **HomeView** — dashboard hierarchy: primary OS/device/security cards, attention row for conflicts, concise scan meta, **Expanders** for identity notes and observation summary, quick navigation tiles  
- **DomainView** — settings cards with Conflict / Unknown badges; conflict cards use left accent border  
- **SettingDetailPage** — primary state first (accent card); What/Why; **Expanders** for observed layers and detailed impact/misconceptions; related settings as navigation  
- **ConflictsView** — layer conflict cards  
- **KnowledgeExplorerView** — catalog browser independent of live values  
- **SearchResultsView** — SettingsQuery-backed search with empty state  
- **AboutView** — mode explanation, philosophy, architecture, safety, shortcuts, project metadata  

### Services

- `ScanService` — mirrors CLI composition; runs pipeline off UI thread; raises status events  

### Styling

- Fluent-inspired light theme: Windows blue accent, neutral grays, card elevation, readable typography  
- Status badge variants (success / warning / conflict / unknown)  
- CardAccent / CardConflict for visual hierarchy  
- Breadcrumb and Expander styles  
- ToolTips on primary chrome  
- No neon, no score gauges, no hacker aesthetics  

### UX polish (final pass)

- Keyboard: F5 / Ctrl+R rescan, Ctrl+F focus search, Esc clears search text  
- Humanized domain titles via `NavigationBuilder.HumanizeDomain`  
- Empty states for domain / search / conflicts  
- Conflict count in status bar  
- Mode control explains future Modify without enabling writes  

### Backend touch

- `MachineOverview` CatalogVersion / KnowledgeBaseVersion defaults set to `1.0`  
- `NavigationBuilder.HumanizeDomain` made public for presentation hosts  

### Unchanged

- Collectors, binders, PolicyPrecedenceResolver, ValueSemantics ownership, CLI, TUI  
- Safety model: read-only, no elevation, no scores  

---

## Architectural decisions

| Decision | Rationale |
|----------|-----------|
| WPF | Fits existing `net8.0-windows` target; no extra SDK; professional desktop UX |
| ScanService in App | Presentation composition only; identical collector/binder/validator path as CLI |
| Views consume SettingDetailView / MachineOverview / SettingsQuery | Existing presentation contract; no Windows logic in UI |
| CLI + TUI retained | Secondary hosts remain valid |
| Modify mode disabled | UX scaffold only; no write path introduced |

---

## Security review

- No write APIs in App  
- No elevation  
- Scan remains fail-soft  
- Unknown preserved  
- Discovered strings displayed only  
- Clipboard used only for explicit user-initiated ObjectId copy  
- Preferences file stores only window geometry and sidebar state  

---

## Limitations remaining after v1.0

- Light theme only (dark / high-contrast can be extended)  
- SemanticValue / ConfidenceReason not yet every surface in TUI (GUI detail shows resolution reason + confidence)  
- No relationship graph visualization beyond lists  
- No export / comparison / history  
- Secure Boot / TPM / BitLocker often Unknown without elevation  
- Firewall profile-level only

```powershell
cd WindowsPrivacyPlatform.App
dotnet run -c Release
```

```powershell
cd Source\WindowsPrivacyPlatform.CLI
dotnet run -c Release
dotnet run -c Release -- --tui
```
