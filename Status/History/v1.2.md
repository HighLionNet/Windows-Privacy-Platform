# History — Version 1.2

**Milestone date:** 2026-07-25  
**Document role:** Historical record of the enterprise GUI refinement (presentation only).

---

## Context

v1.1 removed stacked-card AI aesthetics and introduced MMC-style property sheets. The UI still read as a dense developer tool: typography was flat, the setting detail page dumped everything at once, and hierarchy did not scale toward hundreds or thousands of settings.

Backend remained frozen. This release is presentation-only.

---

## Goals

1. Enterprise management-console presentation maturity (Event Viewer / Services / XDR console density)  
2. Progressive disclosure on the setting detail page  
3. Stronger typography hierarchy and readable spacing  
4. Clearer information architecture: Home answers “what machine?”, Domain answers “what settings and state?”, Detail answers “what is this and what is effective?”  
5. No backend, no scores, no writes  

---

## What changed

### Styles (`AppStyles.xaml`)

- Page titles 20px SemiBold; primary values 15px; body 13px with line-height  
- Increased row/sheet padding and section margins for long reading sessions  
- Stronger HeaderRule and SectionRule spacing  
- DomainTile and ListRow comfort padding  
- DetailExpander weight and spacing  

### Setting detail (largest change)

- Primary surface is now **Effective state** property sheet (Effective first and larger)  
- Short **Summary** (What) always visible  
- All secondary knowledge moved behind expanders (Why/Impact, User/Enterprise/Misconceptions/Limits, Observed layers, Related)  
- Scales: default view stays short even when catalog and knowledge grow  

### Home / Domain / Shell

- Home subtitle tightened; sheets keep single-column property tables  
- Domain list column proportions adjusted  
- Shell: v1.2, slightly larger title/toolbar/content padding, breadcrumb size  
- About product string 1.2  

### Unchanged

- Collectors, binders, PolicyPrecedenceResolver, ValueSemantics, catalog  
- ScanService pipeline  
- CLI / TUI  
- Safety model
