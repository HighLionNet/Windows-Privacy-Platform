# History — Prototype v0.9

**Milestone date:** 2026-07-24  
**Document role:** Historical record of the knowledge-semantics milestone. Preserve decisions and verification.

---

## Context entering v0.9

v0.8 delivered Machine Overview, ConfigurationObservation provenance fields, resilient identity collection, and the Firewall domain. Gaps called out for the next era:

- Raw policy codes (0/1/2/3) still required mental decoding  
- AppPrivacy force codes were hardcoded in PolicyPrecedenceResolver  
- Resolution reasons were short (“policy wins”) rather than educational  
- Confidence did not explain itself  
- Relationship kinds were limited  
- Catalog lacked formal value maps, WhenIgnored, edition/version metadata  

Product rules reaffirmed: read-only, no elevation, no remediation, no scores, Unknown respected, architecture frozen.

---

## Goals of v0.9

Transform the platform from a configuration explorer into a coherent Windows knowledge engine:

1. Catalog-owned **ValueSemantics** (raw → canonical → display)  
2. **ValueSemanticsInterpreter** pure model — never guess  
3. Resolver consumes maps only; no leftover numeric semantic hardcoding  
4. Educational ResolutionReason + ConfidenceReason  
5. Richer RelationshipKind graph  
6. WhenIgnored / CommonMisconception / TypicalEnterpriseUse on knowledge entries  
7. Provenance fully populated on PrivacyBinder and PolicyBinder  
8. Documentation and handoff updated after verification  

---

## What shipped

### Value semantics (knowledge layer)

- `ValueMeaning` + `ValueSemanticsInterpreter` in Models  
- Maps attached via `ManagedObjectCatalog.ApplyKnownSemantics` for:  
  - ConsentStore Allow/Deny/Prompt  
  - Advertising ID 0/1  
  - AllowTelemetry 0–3 (Security/Basic/Enhanced/Full; edition notes)  
  - AppPrivacy LetApps* 0/1/2 → UserControlled / ForceAllow / ForceDeny  
  - Firewall profile enable and inbound defaults  
  - Selected binary policies  
- Missing map → Unknown; never invent meaning  

### Resolver discipline (verified)

- `PolicyPrecedenceResolver` branches on **catalog canonical** names, not raw `"0"`/`"1"`/`"2"`  
- Manual audit: no leftover hardcoded numeric semantic tables in the resolver  
- `NormalizePrivacyToken` remains syntactic normalization of ConsentStore string tokens (literal registry values), not numeric policy decoding  
- LayerRank remains structural precedence only  

### Educational resolution

- `ResolutionReason` explains why a layer is effective  
- `ConfidenceReason` explains confidence  
- `SemanticValue` / `SemanticDisplay` on `ConfigurationResolution`  

### Relationships

- Expanded `RelationshipKind` (IgnoredWhen, AlternativeStorage, UsuallyConfiguredWith, …)  
- Additional curated edges (firewall ↔ MpsSvc, telemetry alternate stores)  

### Evidence maturity

- PrivacyBinder and PolicyBinder populate CollectorName, EvidenceSource, CollectionNotes, EffectiveConfidence  

### Explanations

- `SettingExplanationFactory` prefers catalog WhenIgnored / CommonMisconception / TypicalEnterpriseUse  
- WhatIsIt surfaces known value map when present  

---

## Architectural decisions

| Decision | Rationale |
|----------|-----------|
| Semantics live on ManagedObject / catalog, interpreter pure in Models | Knowledge owns meaning; Scanner still depends only on Models; no dependency inversion required |
| Resolver matches canonical ForceAllow/ForceDeny, not raw digits | Raw→meaning is catalog-only; resolver applies force outcome after interpretation |
| Incomplete maps stay empty | Unknown is correct; expand maps catalog-first |
| No new collectors in v0.9 | Semantics correctness did not require new discovery |

---

## Problems solved

- “What does 0 mean?” is answered from knowledge, not from resolver switch tables  
- Conflict cards can carry educational precedence language  
- Future GUI detail view has a contract for SemanticValue + ConfidenceReason + WhenIgnored  

---

## Security review outcomes

- No write APIs  
- No elevation  
- No new network paths  
- Unknown preserved when maps or evidence are missing  

---

## Limitations remaining after v0.9

- Not every catalog ObjectId has a ValueSemantics map yet  
- TUI/CLI do not fully render SemanticValue / ConfidenceReason on every detail surface  
- No dedicated relationship exploration query API beyond StructuredRelationships  
- MDM/baseline collection still incomplete  
- Firewall still profile-level  
- No scan history / comparison  
- No GUI  

---

## Transition to next era

v0.9 closes the “hardcoded Windows meaning in resolvers” chapter. Next priorities: surface semantics/evidence in presentation, relationship query shapes, careful domain depth (Defender / Update / firewall rules), still read-only. See `Status/Roadmap.md`.
