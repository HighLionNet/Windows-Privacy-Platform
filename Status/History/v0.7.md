# History — Prototype v0.7

**Milestone date:** 2026-07-24 (archived as completed before v0.8)  
**Document role:** Historical record. Do not overwrite with summaries that erase decisions.

---

## Context entering v0.7

v0.6 FINAL had established the understanding foundation:

- ProductDomain taxonomy on catalog entries  
- Domain snapshot sections on InventorySnapshot  
- Split binders (Privacy / Policy)  
- PolicyPrecedenceResolver + ConfigurationResolution  
- SettingExplanation, SettingsQuery, NavigationBuilder  
- CLI conflict decision cards  
- ~65 curated catalog entries  
- Strictly read-only pipeline  

The product could bind observations, resolve known layer conflicts, and print decision cards, but presentation was still primarily **report-oriented**.

---

## Goals of v0.7

Make the intelligence **navigable and human-facing** without changing architecture or safety posture:

1. Thin read-only TUI (`--tui`)  
2. Explanation quality (documentation tone, misconceptions, unknowns)  
3. Observed vs Interpretation separation in cards  
4. Human relationship phrasing  
5. Neutral impact language (not a security score)  
6. CapabilityCollector transparency when results are empty  
7. Documentation rewritten as engineering journal  

---

## What shipped

### TUI (`TuiHost.cs`)

- Keyboard domain → category → setting → documentation card  
- Alternate screen buffer where supported  
- Consumes **only** NavigationBuilder, SettingsQuery, SettingDetailView  
- **No business logic in UI**  

### Explanation system

- SettingExplanationFactory expanded narrative fields  
- Neutral ImpactLabel wording  
- Common misconceptions and unknowns called out explicitly  

### Relationships

- Expanded curated pairs (Advertising, Location, Activity History, Search groups) while keeping Consent↔AppPrivacy and dual telemetry paths  
- Presentation phrases: “Controlled by”, “Also related to”, “Potential conflicts”  

### CapabilityCollector

- Multi-shell / DISM attempts  
- CLI explicitly explains zero results as collection uncertainty (Unknown), not “nothing installed”  

### Language

- “High-impact watch list” instead of score framing  
- RiskLevel enum retained in data model for compatibility; UI says impact  

---

## Architectural decisions (kept)

- Seven-project dependency graph unchanged  
- Precedence only in PolicyPrecedenceResolver  
- Models remain pure data  
- No remediation, no elevation, no writes  
- Firewall domain remained **reserved** (enum only, no entries)  

---

## Problems solved

- Users could explore effective-layer stories interactively instead of only scrolling reports.  
- Empty capability lists stopped being easy to misread as “zero installed.”  
- Explanation tone moved from registry metadata toward technical education.  

---

## Important discoveries

- Console TUI is enough to validate the application API (SettingsQuery / NavigationBuilder) before any GUI framework.  
- Documentation quality is part of the product surface area; Status docs were rewritten as a handbook, not release-note fluff.  

---

## Limitations remaining at end of v0.7

- No Machine Overview separation  
- No formal multi-field provenance on observations  
- Identity still largely single-source registry  
- Firewall still empty  
- MDM layers ranked but not collected  
- Relationship graph still curated and incomplete by design  

---

## Why v0.8 was next

v0.7 proved navigation and explanation. The next gap was **device context**, **evidence honesty**, and the first real **security domain expansion** (Firewall) without becoming a control tool — addressed in `Status/History/v0.8.md`.
