# History — Prototype v0.8

**Milestone date:** 2026-07-24  
**Document role:** Historical record of the intelligence-foundation milestone. Preserve decisions and discoveries.

---

## Context entering v0.8

v0.7 delivered a navigable TUI and improved explanation cards on top of the v0.6 understanding foundation. Gaps called out explicitly:

- No dedicated Machine Overview (device context mixed poorly with configuration trees if forced in)  
- Observations lacked structured provenance (“How do you know?”)  
- Identity collector was mostly single-path registry  
- Firewall domain was reserved only  
- TUI started at domain list, not a Home / machine context step  

Product rules reaffirmed before coding: read-only, no elevation, no remediation, no scores, Unknown respected, architecture frozen.

---

## Goals of v0.8

Strengthen the intelligence foundation (quality over feature count):

1. Machine Overview as a separate concept from configuration exploration  
2. Evidence / provenance fields on ConfigurationObservation  
3. Multi-source resilient WindowsIdentityCollector  
4. Firewall domain: curated catalog + read-only collector  
5. TUI Home structure preparing future GUI hierarchy  
6. Documentation updates after implementation  

---

## What shipped

### Machine Overview

- Pure-data `MachineOverview` model built from `InventorySnapshot`  
- Fields: OS/edition/build/architecture, manufacturer/model/processor/memory, Secure Boot/TPM/BitLocker placeholders, domain/Entra placeholders, PowerShell/.NET, firewall/Defender service summaries, scan/catalog/KB metadata, identity confidence + notes  
- CLI default report prints Machine Overview **before** configuration summary  
- Explicit framing: observed platform information — **not a security score**  
- Unknown states remain visible with collection notes  

### Evidence / provenance foundation

Extended `ConfigurationObservation` with:

- CollectorName  
- EvidenceSource  
- AlternativeSources  
- CollectionNotes  
- EffectiveConfidence  

Backward compatible with Layer / RawValue / SourcePath / ObservedAt / ConfidenceScore.

### WindowsIdentityCollector resilience

- Primary: HKLM `SOFTWARE\Microsoft\Windows NT\CurrentVersion`  
- Cross-checks: RuntimeInformation, Environment fallback, optional WMI/CIM (`Win32_OperatingSystem`, `Win32_ComputerSystem`, `Win32_Processor`)  
- Agreement raises confidence; conflicts and missing providers produce notes + Unknown  
- Package: `System.Management` added to Scanner (fail-soft if WMI blocked)  
- No elevation  

### Firewall domain

- Catalog-first curated entries (Domain/Private/Public enabled, inbound defaults, MpsSvc, logging summary)  
- Neutral documentation-style What/Why text  
- `FirewallCollector`: read-only registry under SharedAccess FirewallPolicy + ServiceController for MpsSvc (and Defender service hint)  
- `InventoryStateBinder` maps snapshot profiles into Firewall catalog ObjectIds with provenance  
- **No** rule enable/disable, **no** netsh mutation, **no** policy writes  

### TUI / GUI preparation

- Home screen: Machine Overview | Explore Domains | Search  
- Machine Overview screen scrollable; Esc returns to Home  
- Domains exploration path preserved  
- Version string bumped to v0.8  

### Packaging / wiring

- FirewallCollector registered in CLI collector list  
- ManagedObjectCatalog.All concatenates Privacy + Policy + Firewall batches

## Architectural decisions

| Decision | Rationale |
|----------|-----------|
| Keep seven-project graph | Architecture stable; v0.8 is additive |
| Machine Overview outside domain tree | Prevents polluting configuration navigation with hardware context |
| Provenance on ConfigurationObservation, not a parallel model | Avoid duplicate observation systems |
| Firewall profile-level only | Understanding first; rule inventory can come later without control APIs |
| WMI optional | Many hosts restrict WMI; Unknown is better than crash or elevation |
| Presentation truncation of long overview lines | Intentional UI behavior, not data corruption |

## Problems solved

- Users can answer “What is this computer?” before diving into ConsentStore/GPO trees.  
- Observations can carry “how we know” fields for future detail cards.  
- Identity is less brittle when one provider fails.  
- First real security domain (Firewall) demonstrates catalog → collector → bind → navigate without becoming a firewall manager.  

---

## Important discoveries

- Secure Boot / TPM / BitLocker / Entra often cannot be verified with non-elevated read-only APIs; product must stay honest (Unknown + notes).  
- Firewall registry profile keys are a practical read-only source; full rule enumeration is a separate, larger surface.  
- Separating Home / Machine Overview early reduces pressure to overload setting cards.  
- Human validation note: shortened display of some overview values was **presentation**, not collector corruption.  

---

## Security review outcomes

- No write APIs introduced.  
- No elevation helpers.  
- FirewallCollector uses Registry open read-only + ServiceController status only.  
- Identity WMI path fully try/caught.  
- Safety confirmation text updated to mention firewall rules not modified.  

---

## Limitations remaining after v0.8

- Provenance fields not yet fully rendered on every TUI detail card section.  
- No KnowledgeBase value-semantics dictionary for raw policy codes.  
- No relationship “query everything affecting X” API beyond existing SettingsQuery edges.  
- Firewall not per-rule.  
- MDM/baseline collection still incomplete.  
- No scan history / comparison.  
- Status AI_Handoff / Project_Documentation still partially v0.7-framed until refreshed.  

---

## Transition to next era

v0.8 closes the “scanner that grew explanations” chapter and opens the **deep Windows understanding platform** chapter: evidence maturity, value semantics, relationship exploration, careful domain depth — still without becoming an action tool. See `Status/Roadmap.md`.
