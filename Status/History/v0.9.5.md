# History — Prototype v0.9.5

**Milestone date:** 2026-07-24  
**Document role:** Historical record of the knowledge-maturity milestone. Preserve decisions and verification.

---

## Context entering v0.9.5

v0.9 delivered ValueSemantics, educational resolution, provenance maturity, and relationship expansion. Gaps remaining:

- Many PolicyCollector probes had no catalog entry
- ValueSemantics maps covered only high-value subsets
- AppPrivacy–ConsentStore relationship graph was incomplete (4 pairs)
- Validator performed only per-object structural checks
- Compatibility / WhenIgnored / CommonMisconception coverage uneven

Architecture remained frozen; this milestone is pure knowledge enrichment.

---

## Goals of v0.9.5

1. Catalog entries for every PolicyCollector probe + missing ConsentStore capabilities
2. Expanded ValueSemantics (AUOptions, DODownloadMode, Spynet, Samples, Edge Tracking, full binary set)
3. Full AppPrivacy–ConsentStore relationship wiring (14 pairs)
4. Additional curated relationship edges (Defender, Update, Search, Location)
5. SchemaValidator unique-ObjectId batch guard
6. SchemaVersion 0.9.5; educational fields populated where known
7. Documentation and handoff updated

---

## What shipped

### Catalog

- Privacy batch expanded with phoneCall, chat, bluetoothSync, cellularData, wifiData, userDataSystem
- Policy batch now covers all PolicyCollector probes (telemetry, update, Defender, search, activity, cloud, advertising, location, full AppPrivacy LetApps*, device, feedback, OneDrive, Explorer, biometrics, Edge)
- Firewall batch unchanged (already complete)
- Every entry carries SchemaVersion 0.9.5 and ConfidenceSource Catalog-v0.9.5

### ValueSemantics

- ConsentStore Allow/Deny/Prompt (unchanged pattern)
- AppPrivacy 0/1/2 UserControlled/ForceAllow/ForceDeny (all LetApps*)
- AllowTelemetry 0–3 with edition notes
- AUOptions 2–5
- DODownloadMode 0/1/2/3/99/100
- SpynetReporting 0–2
- SubmitSamplesConsent 0–3
- Edge TrackingPrevention 0–3
- Binary 0/1 maps for the large set of polarity policies

### Relationships

- ConsentPolicyPairs expanded from 4 to 14 capability pairs
- RelatedPairs added for Defender real-time stack, Update AU scheduling, Search cloud, Location provider, tailored experiences alternate path

### Validator

- ValidateAll detects duplicate ObjectIds across the batch and fails those entries

### Architecture impact

- None. Models remain pure. Collectors unchanged. Resolver unchanged. CLI/TUI presentation-only. Dependency direction preserved.

---

## Security review outcomes

- No write APIs
- No elevation
- No new network paths
- Unknown preserved when maps or evidence are missing
- Catalog quality guard reduces risk of silent duplicate IDs

---

## Limitations remaining after v0.9.5

- TUI/CLI still do not fully surface SemanticValue / ConfidenceReason on every detail card
- No dedicated relationship exploration query API beyond StructuredRelationships
- MDM/baseline collection still incomplete
- Firewall still profile-level
- Secure Boot / TPM / BitLocker / VBS still largely Unknown without elevation
- No scan history / comparison
- No GUI

---

Next priorities remain presentation of semantics/evidence, relationship query shapes, and careful domain depth (Defender platform info, Update, firewall rules) — still read-only. See `Status/Roadmap.md`.
